# SealSkin 0.5.1

Maintenance release. On Kubernetes, SealSkin now installs with a namespace's
own admin role, and its administrators shape session pods in SealSkin's
settings without any access to the namespace. Launches behind a proxy that
gives up on long requests now reach their session, and sessions open once
their stream is ready.

## Kubernetes

* **Installs with the namespace admin role alone.** `kubernetes/sealskin.yml`
  no longer asks for PodTemplates, which Kubernetes' own namespace roles do
  not grant, so a namespace administrator who is not a cluster administrator
  can apply it. The PodTemplate read grant and the `sealskin-session`
  template moved to `kubernetes/pod-templates.yml`, for whoever may apply
  them.
* **Pod overlays.** `kubernetes_session_overlay` (under every session pod),
  `KUBERNETES_POD_OVERLAY` in an app template (under its applications'
  pods), and `kubernetes_gpu_options` (the GPU options) take YAML of a pod
  template, kept in SealSkin and edited in the dashboard. They take labels
  and annotations, placement, runtime, priority, DNS and security fields,
  image pull secrets, device claims, and the application container's
  resources and security context, and refuse anything else by name, so an
  administrator of SealSkin reaches none of the namespace's objects through
  them. PodTemplates stay as an optional layer beneath.

## Fixes

* A launch behind a reverse proxy that ends long requests with 502, 503, or
  504 is followed to its session, or to the server's own reason, instead of
  failing with the proxy's page. This covers the launcher, the extension's
  popup, the App Laboratory, the Bakery's trial, and application addresses.
* A session opens once Selkies' stream route answers rather than when the
  container's web server first does, so a stream opened right after launch
  is no longer refused.
* The app stores' autostart scripts are fetched eight at a time over one
  client, which ends the bursts of failed fetches on nodes of large
  clusters.
* The dashboard's certificate notice shows the days left instead of
  `{days}`.
* The cookie of a root key sign-in is handed out again with a token the
  server mints, at most once a day, instead of the one the browser sent.
  Signing out with either ends both.

## Sign-in

* The **Sign In** test says whether the OpenID Connect scopes ask for
  `offline_access`, and warns when the provider offers it and they do not.
  Without a refresh token a sign-in ends with its ID token, which some
  providers issue for only minutes, so users were asked to sign in on nearly
  every visit. The server also logs, once an hour, a sign-in that comes back
  short for want of a refresh token, and the Authentik preset says to give
  the provider the scope.

## Upgrading

* **Kubernetes:** applying the new `kubernetes/sealskin.yml` over an
  existing install takes away the server's access to PodTemplates. If you use
  the `sealskin-session` template, `KUBERNETES_POD_TEMPLATE`, or GPU
  templates, also apply `kubernetes/pod-templates.yml` as someone allowed to
  grant access to PodTemplates, or move them into the new pod overlay
  settings. Without the grant, the server treats PodTemplates as absent.
* **OpenID Connect:** if users have to sign in on nearly every visit, add
  `offline_access` to the scopes, and to the provider's scopes where it asks
  for that, as Authentik does. The **Sign In** test shows whether it is
  needed.

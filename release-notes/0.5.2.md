# SealSkin 0.5.2

Maintenance release.

## Collaboration

* **Collaboration profiles.** An administrator assigns a profile to users
  and groups under **Collaboration profile**, and it decides what their
  collaboration rooms may do. Chat, cameras, microphones, the application
  switcher, mouse and keyboard handoff, gamepads, collaborator invites, and
  viewer invites can each be turned off, and collaborators can be kept from
  sharing viewer invites. A profile can also keep the stream at the
  controller's resolution and cap how many people may join a room. The
  server refuses whatever a profile turns off, whatever a guest's page
  sends. Where a user's groups name several profiles, each feature takes the
  most restrictive. A room keeps the rules it started under. The form
  previews the room's bar as the controller, a collaborator, and a viewer see
  it. Profiles are kept in the shared record `collaboration_profiles.yml`
  (`SEALSKIN_COLLABORATION_PROFILES_PATH`). A user under no profile gets
  every feature, as before.
* **People in a room.** The room's bar has a people button that lists
  everyone in the room, viewers included, with whether their microphone and
  camera are on and what input they hold. The controller can hand a
  collaborator the mouse and keyboard from it. Bugfix: A participant whose 
  camera is off keeps a tile.

## Fixes

* With `SEALSKIN_AUTO_SIGN_IN=oidc`, an application's address such as
  `/app/<app_id>/` is now kept through the identity provider's round trip,
  so the user lands on that application after signing in rather than on the
  home page.
